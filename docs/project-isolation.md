# Project transfer and change export

The default project is the current directory; `--project` selects another. No writable host mounts are created. Source identity is the canonical absolute directory plus a SHA-256-derived suffix; moving a source directory creates a new identity. Each conversation gets `~/.agent-vm/workspaces/PROJECT/SESSION_UUID` in its VM. Multiple projects and conversations can share a VM without overwriting one another's working trees.

For a Git repository (including a worktree with an external `.git` file), Git selects tracked files and untracked nonignored files using NUL-delimited `ls-files`. Current working-tree bytes are copied, so modifications are preserved; already deleted tracked files stay absent. A `.git` file/directory is never copied. The guest receives a newly initialized, self-contained Git repository with a baseline commit reflecting the copied state. It does **not** receive the host's original Git history, remotes, hooks, worktree metadata, index staging distinctions, or global Git configuration. This intentionally avoids dependencies on inaccessible host Git paths and private remote credentials. An unborn repository also works.

For a non-Git directory, regular files and safe relative symlinks are copied recursively using the same exclusions; Git ignore rules are not interpreted outside a repository. Relative symlinks escaping the source and absolute symlinks are rejected. Special files and Git submodules are rejected explicitly. Nested repositories, Git LFS object hydration, alternate object databases, sparse-checkout semantics and original repository history operations are not supported. LFS pointers are ordinary file bytes; hydrate needed files before snapshotting and review before launch.

Ignored Git files are omitted, including ignored local builds. These additional components are excluded even when tracked: `.git`, `node_modules`, `vendor`, `.venv`, `venv`, `.aws`, `.ssh`, `.codex`, `.claude`, `.cursor`, `.agent-vm`, `.docker`, `.kube`, `.npmrc`, `.netrc`, `.pypirc`, `id_rsa`, `id_ed25519`, `.DS_Store`, names starting `.env` except `.env.example`, and suffixes `.pem`/`.key`. Agent project config directories are excluded to avoid importing credentials/custom integrations. Dependencies must be installed in the guest. These are defined exclusions, not a general secret scanner; inspect the source before transfer, especially secrets in other filenames and `.env.example`.

The source must be reasonably quiescent while copied. No filesystem-wide atomic host snapshot is promised; concurrent edits can produce a mixed-time copy. Host files are never modified. A fresh `run` takes a new snapshot; existing guest changes remain in the prior conversation's directory. Resume and attach do not transfer any host files. There is no implicit host/guest synchronization or “refresh workspace” overwrite operation.

Transfer uses a private temporary tar containing the independent repository, carried over verified SSH stdin into an exclusively created guest directory. Partial failures preserve the registry record and partially transferred directory for inspection. Repeating `run` creates a new conversation/directory; it never overwrites that failed copy. `sessions show` reports the preparing state when launch did not finish. Remove abandoned guest directories explicitly after review, or delete the whole owned VM when appropriate.

Export requires the managed process to have exited, but other shells/processes can still edit files: stop those too for a consistent snapshot. The stored initial baseline hash (not the agent's latest HEAD) anchors `git diff --binary --no-ext-diff`, so committed and uncommitted tracked changes, executable bits, binary data and deletions are retained. The current workspace tar adds untracked/ignored files and content. `status.bin` is NUL-delimited porcelain v1; `baseline.txt` identifies the baseline. The complete archive is mode 0600 and must be written to a new path. It is never applied to the host. Inspect extraction paths and contents in a separate directory before using exported files.

Native histories live in each harness's persistent guest account directories, outside the workspace archive. Export is a change-review artifact, not a conversation backup or VM recovery mechanism.
