# Agent support matrix

Verified against official documentation and tagged source on 2026-10-24. **No vendor account/login was used and no native harness was run inside a VM.** Commands below are implementation targets, not claims of live validation. Both guest OS choices use ARM64 binaries and are independent of the agent choice.

| Capability | Codex CLI 0.164.0 | Claude Code 2.1.310 | Cursor Agent 2026.10.22-27dcf5f |
|---|---|---|---|
| Executable | `codex` | `claude` | `agent` (`cursor-agent` is vendor legacy alias) |
| Fresh interactive launch | `codex [args] -- prompt` | `claude --session-id UUID [args] -- prompt` | `agent create-chat`, then `agent --resume ID [args] -- prompt` |
| Initial ID | Generated by harness | Tool supplies UUID | Explicit `create-chat` returns ID |
| Resume | `codex resume ID` | `claude --resume ID` | `agent --resume ID` |
| Attach | Managed tmux process | Managed tmux process | Managed tmux process |
| Automatic history association | Structured JSONL session_meta, exact cwd, one CLI conversation | Structured JSONL sessionId/cwd, exact workspace/recorded UUID | Unsupported; explicit history binding required |
| Newer/other history layouts | Fail explicitly; bind native ID/file manually | Fail explicitly; bind native ID/file manually | No verified structured saved-history inventory; `ls` is interactive and is not scraped |
| Subscription auth | Guest ChatGPT sign-in, or explicit file auth-cache import | Guest `claude auth login` | Guest `agent login` |
| API credentials | Guest `OPENAI_API_KEY` login via stdin | Guest `ANTHROPIC_API_KEY` environment | Guest `CURSOR_API_KEY` environment |
| Auth preflight | `codex login status`, success exit code | `claude auth status`, success exit code | `agent status --format json` command available, but authentication schema/exit semantics remain unverified; native CLI decides |
| Linux/macOS live validation | Pending / pending | Pending / pending | Pending / pending |

The Codex JSONL reader is a narrowly pinned format reader, **not a stable public discovery API**. Codex 0.164.0 also supports newer paginated history; automatic association for that layout is not implemented. Its app-server API is marked experimental in tagged CLI source, so this release does not introduce that API or require a daemon. This is a material first-release limitation: where JSONL is absent, obtain the exact ID through the native CLI and bind its existing guest history file. Do not select “latest” as an identity substitute.

Cursor `create-chat` creates an empty native conversation for a fresh tool session; using its returned ID does not continue an unrelated chat. The command's documented ID response is validated as an identifier. A verified local-history-file discovery API was not found; the user must identify the actual saved file and bind it before native resume through agent-vm. Live `attach` remains available without discovery. `resume` (including its picker) requires saved-history verification even when attaching; use `attach` if only process attachment is available.

Claude's public CLI provides a caller-selected UUID, removing ID ambiguity. This release recognizes persisted project JSONL records, but does not use Claude's native background agents or their attachment mechanism. It uses the same tmux process boundary as the other adapters.

Arbitrary safe harness arguments go after `--`. Managed resume/workspace/background/print/credential controls are rejected, including attached managed short flags. Additional argv is preserved and retained for native resume. Do not put credentials in arguments: use the documented auth paths. A second `--` is inserted before the initial prompt so prompt text cannot become a native subcommand or flag. Terminal quoting is tested, while exact vendor parsing with these targeted versions still requires the live checks.
